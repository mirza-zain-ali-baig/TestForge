ExamForge QA Report — All Errors & UI/UX Issues
🔴 CRITICAL BUGS (App-breaking)
1. AI Chat crashes the entire application
Steps: Navigate to AI Chat → type a message (or click any suggestion button like "Generate Exam MCQs") → click Send
Result: The whole Next.js app crashes with Application error: a client-side exception has occurred while loading generate-test.vercel.app (see the browser console for more information). The page must be reloaded; state is lost.
Reproducibility: 100% — crashed on both typed message and suggestion-button click.
Impact: A core advertised feature (AI Chat / AI Assistant) is completely unusable.
2. Long Answer section never renders in generated paper
Steps: In Test Setup add any Long Answer questions (e.g. 1 or 2) → click "Generate Printable Paper".
Result: The generated paper contains only SECTION A — MCQ and SECTION B — SHORT. SECTION C (Long Answer) is missing entirely, even though the question count and mark total in the focus-mode summary (e.g. 5 Q · 7 marks) excludes the Long Answer questions that were configured.
Impact: Users who configure long-answer questions silently lose them.
3. "Back" button on paper view resets the entire workflow
Steps: Generate a paper → click the "Back" button in the paper toolbar.
Result: Instead of returning one step back to "Test Setup", the workflow resets all the way to Step 1 — Select Class. All question breakdown config (marks per question, counts, source filter, etc.) is lost.
Impact: Users lose their entire test configuration by clicking Back.
4. "Save" button fails silently with role authorization error
Steps: Register a new account (default role = student) → generate a paper → click Save.
Result: Toast: Access denied: role "student" is not authorized to save test papers. Required role: educator or admin.
Issues: (a) The registration form never asks for a role, so all new users are silently student. (b) The Save button is still rendered/active for student users instead of being hidden or disabled with a tooltip. (c) No way exists in-app for the user to upgrade their role.
🟠 HIGH-SEVERITY BUGS
5. Data inconsistency: question counts don't match
The site shows three different totals for the question bank:

Dashboard stat card: Questions 2,123 (this matches 891 Class 9 + 1,232 Class 10)
Dashboard "Browse questions" CTA: "2,773-question bank" ← wrong by +650
The chapter filters in Question Bank correctly total 891/1,232 — so the 2,773 number is fabricated.
6. "Regenerate question with AI" and "Explain answer with AI" buttons do nothing
Clicking either button on a question in the paper produces no visible UI change — no loading spinner, no toast, no modal, no error, no inline explanation. The buttons appear dead.
7. Practice Online silently drops non-MCQ questions
The paper has 5 questions (3 MCQ + 2 Short). Practice Online mode shows only the 3 MCQs (TOTAL MCQS: 3) and offers no warning that Short Answer questions were excluded.
Footer text "MCQs are auto-graded. Written answers show the model answer for self-assessment" implies Short Answers should be included — they aren't.
8. Question Bank "Favorites" filter does not visually activate
The Favorites / All toggle buttons have no aria-pressed or pressed visual state, so users can't tell which filter is active.
Clicking "Favorites" with no favorites in the current search result set shows no empty state — it just continues showing the same search results.
9. Edit Question modal has unlabeled form fields
All textboxes in the Edit Question modal have no label text (just textbox [ref=...] in the a11y tree). The "Bloom's level" and "Tags" fields are also unlabeled.
The A/B/C/D buttons for marking the correct answer are labeled only with the letter — no "Mark as correct" tooltip or aria-label.
Major screen-reader accessibility failure.
10. "Marks per question" spinbuttons have duplicate accessible names
Three spinbuttons (for MCQ/Short/Long marks) all share the accessible name "Marks per question". A screen reader can't distinguish them.
The count spinbuttons have accessible name "0" (their current value) — also non-descriptive; should be e.g. "MCQ count".
